# Portfolio

React portfolio using Firebase Authentication, Cloud Firestore, and static Firebase Hosting. Cloud Storage and Cloud Functions are not required.

## No billing account required

Use the Firebase **Spark** plan and the default Firestore database. Firestore's free quota includes 1 GiB stored data, 50,000 reads/day, 20,000 writes/day, 20,000 deletes/day, and 10 GiB outbound transfer/month. These are usage limits, not unlimited service. On Spark, exceeding quota can interrupt service; enabling Blaze can incur charges. Code changes do not change the project's billing plan.

See https://firebase.google.com/docs/firestore/quotas and https://firebase.google.com/docs/projects/billing/firebase-pricing-plans.

## Configuration

Set these existing Firebase web-app values in `.env.local`:

```
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=...
VITE_FIREBASE_PROJECT_ID=...
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
```

Enable email/password Authentication for the admin. Verify the admin UID in `firestore.rules` matches your account. No storage bucket setting is needed.

## Images and comments

Admin images are resized in the browser and saved as JPEG data URLs in Firestore, up to 250,000 encoded characters each. Admin forms reject payloads above 900,000 UTF-8 JSON bytes, leaving room below Firestore's 1 MiB document limit. Multiple images share that document budget. Use smaller images or static image paths such as `/home.jpg` for larger collections. Existing URL fields remain supported; large downloads such as a CV use a static file or external URL.

Optional comment avatars are compressed to at most 160 pixels on the longest edge and 32,000 encoded characters, then saved in the same Firestore document as the comment. New avatar writes accept only JPEG data URLs or null. Existing URL-based avatars remain readable, but any old Cloud Storage URL still depends on its original bucket; re-upload such images to migrate them. This change does not access or migrate live data or delete existing buckets.

The guestbook subscribes to the latest 50 comments to bound initial reads and image transfer. Image fields are exempted from indexing. Public comment/contact submissions are validated in Firestore rules; these rules do not provide hard per-visitor rate limits.

## Check and deploy

```
npm install
npm test
npm run lint
npm run build
firebase deploy --only firestore,hosting
```

Deploy both the updated Firestore rules/indexes and Hosting together: the old comment rules reject embedded avatars. Deployment needs Firebase CLI authentication. The tracked `dist` directory is regenerated by the build.

## Initial loading screen

The HTML includes a loading message before JavaScript starts. The full-screen React loader stays visible until the main profile document arrives from Firestore, then reveals the page immediately without a fixed welcome delay. Other sections load independently. Failed reads or a 15-second timeout show a retry button; missing settings do not leave the loader spinning forever. The loader and profile sections share one subscription.
